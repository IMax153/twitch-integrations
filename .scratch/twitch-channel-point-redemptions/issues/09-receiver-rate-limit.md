# 09: Decide the rate limit on the receiver route

**What to build:** Twitch publishes no source IP ranges, so the receiver cannot allowlist and a rate limit is the remaining guard against a flood on the public route. Find out whether Alchemy can declare a Cloudflare rate-limiting rule on the `/eventsub*` route as an ordinary resource in the stack. If it can, add the rule at a threshold well above Twitch's plausible delivery rate for one channel and verify it appears in the plan. If it cannot, or needs a plan or product the zone does not have, record that outcome and the reasoning in the spec's receiver section and in the ADR 0002 amendment, so the decision is written down either way.

**Blocked by:** 03

## Comments

Implemented on 2026-09-12. Alchemy 2.0.0-beta.77 has the resource: `Cloudflare.Ruleset.Ruleset` owns one phase entrypoint of a zone, and `http_ratelimit` is among its typed phases, with the rule type carrying `ratelimit.characteristics`, `period`, `requestsPerPeriod`, and `mitigationTimeout`. It takes a `Cloudflare.Zone.Zone` resource, so `apps/infra/src/Zone.ts` adopts the existing `minbadblue.com` zone with `adopt(true)`; the zone provider brands a pre-existing zone as unowned, adoption only reads and, if type or pause differed, patches it, and Alchemy's default for zones retains them on destroy. `apps/eventsub/src/RateLimit.ts` declares the rule and the stack yields it after the receiver Worker, skipped under `alchemy dev` like the Access resources. Read from the live API: the zone is on the Free plan, whose rate-limiting rules (per Cloudflare's availability table) allow one rule, a rule expression on the path and verified-bot fields only, counting by source IP only, and a fixed ten-second period and ten-second mitigation timeout. The rule is therefore `starts_with(http.request.uri.path, "/eventsub")` on the shared prefix from `Domain.ts`, action block, matching that prefix on every hostname in the zone since the Free plan's expression cannot name the host, a hundred requests per ten seconds per source IP, justified in the comment on `requestsPerPeriod`. `alchemy plan --stage production` from the worktree shows `[EventSubRateLimit] create` and `[Zone] adopted` with every other resource exactly as in the baseline plan (the three Workers as updates, as always, the rest noop). Spec receiver section and the ADR 0002 amendment of 2026-09-12 record the rule, its Free-plan limits, and what it does not cover. No tests: the change is configuration with no behavior a unit test could exercise, and the plan is the verification.

Reviewed on 2026-09-12 on both axes. Applied: the `/eventsub` prefix is one constant in `Domain.ts` shared by the route, the callback path, and the rule; the period constant is named for what it is, seconds; the Zone doc no longer claims adoption only reads, since Alchemy syncs type and pause settings, which already match; the spec and ADR say the rule covers the prefix on every hostname in the zone; the time-bound fact about the profile's missing scope lives here and in ticket 10 rather than in the spec and ADR; the not-applicable box is left unticked. Kept: `done` as the status, matching tickets 04 to 08, with the deploy prerequisites noted on ticket 10 where the human verification starts.

Flagged for the deploy: the Alchemy Cloudflare profile carries `zone.read` but no `zone-waf` scope, so a read-only probe of the zone's rulesets endpoints with its token answered "Authentication error". The plan did not hit this because the ruleset's `read` returns before any API call when there is no prior state. The deploy will fail at the ruleset's `PUT` until `alchemy profile edit` re-authorizes the profile with `zone-waf.write` added. The resource owns the whole `http_ratelimit` phase, so any rule made by hand in the dashboard in that phase would be replaced; none is known to exist, and the probe could not confirm it for the same scope reason. Whether the Free plan accepts `starts_with` in the expression is also only confirmed at deploy; the dashboard offers "starts with" on the path field for Free-plan rules, and the fallback is `http.request.uri.path eq "/eventsub/twitch"`.
